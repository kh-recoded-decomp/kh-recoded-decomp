## Templates, runtime copies and physical layout

Text frames and window styles are 16-byte packed records even when a physical definition uses four u32 values instead of eight u16 values. Widget-manager configurations are also 16 bytes, but are a different layout. Consumers copy these templates into locals and replace resource or window fields there. Those local edits do not mutate the stored DATA template or prove every remaining field's meaning.

The status panel and record tile sources likewise start with a stored zero word that is replaced by a pointer to a local copy of tile IDs. That zero is a runtime template placeholder. A port must preserve the pointer setup and the lifetime required by InitTileTableFrom; this naming block does not prove that initializer retains a reference to the local arrays or requires them to outlive the call.

The save-selection layout is 24 bytes containing three 8-byte 2D positions: cursor, empty slot and filled slot. Initialization replaces the local empty-slot position with widget 7's current position, applies the cursor and advances local y values for successive rows. It is not an array of two 12-byte VecFx32 vectors.

## Status rows and tiers

The status text frames are named by the actual textLayers indices passed to InitTextLayerAt. The panel title/body frames are separate objects. gStatusPanelRowLayout contains eight packed byte triplets used as left, width and top when drawing rows; the physical six-u32 declaration represents those 24 bytes and does not define six independent parameters.

gStatusTierThresholds stores four words. The current consumer tests only the first three against the u16 at SelectionPackedValueBlock+0x0a and returns a tier subject to session/mode guards. The legacy GetPlayerLevelTier/PlayerStats.level names do not independently establish units or a gameplay level contract for that field. The DATA name therefore describes thresholds without assigning those units.

## Tutorial owners and fallback text

The root tutorial widget configuration is passed to the manager at GetMenuWork, with archive entry 2 patched into the local copy. The other configuration is passed to the separate GetMenuWidgetContainer result, with archive entry 4. This evidence distinguishes the owners; no display engine or primary/secondary suboverlay lifecycle is assigned from their positions.

The single-page counter fallback is the UTF-16 literal space followed by 1/1; its physical extent is six u16 values including two zero words. The indicator fallback stores ten 0x3000 code units followed by zeros in a 36-byte u32-packed object. Neither object is a numeric counter array, and neither is reduced to its visible string length.

## Shop categories, factors and presets

gShopTabFilterCodes is physically three u16 values but is read as signed bytes. The five demonstrated tab codes are -1,3,2,0,-2; traversal chooses four or five tabs according to the extra-tab setting. The sixth stored zero byte remains part of the physical object and has no additional role inferred here.

The sell-price factor index is the first record word's low two bits. The second word supplies a seven-bit factor used in the existing integer expression. Four factor positions are addressable by that index, while five u16 values are stored. No named quality or rarity is assigned to those positions, and the expression's truncation order remains unchanged.

The category table stores six contiguous IDs in two groups of three. Special kind -1 may pass all six IDs in owned-list mode, crossing the nominal primary/secondary array-member boundary; special kind -2 uses the second three. Preserve the contiguous layout and the actual category count.

The two-choice model camera presets are two four-word records selected by menu mask 0x8000. Their demonstrated fields are height, targetX, targetY and depth for the model draw camera; no gameplay camera mode or meaning for that bit is inferred.

## Grid state and carousel text

The overlay088 grid table holds six rows of three widget IDs. ApplyOverlay088GridStates reads 18 session bits at 0x1e05, maps bit 17 down to bit 0 in row order, finds the corresponding widget and applies animation frame 0 or 1. This proves widget state, not unlocked or completed gameplay content.

The carousel position starts from its stored y/z template while x is replaced for each draw. The base text frame is copied and then locally changed for several text layers. Language index 2 selects the UTF-16 space-colon-space title separator; all other language IDs use colon-space. No human-language name is assigned solely from that numeric ID, and both eight-byte physical separator objects are preserved.
